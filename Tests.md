
Проверял вручную через DevTools → Console на https://kuchersvn.github.io/Projects/
после коммита `fix: валидация структуры записей при загрузке из localStorage`.

 Сценарии

 1. Битые записи в localStorage
Подкладывал массив, в котором часть записей без `title`/`description`, а также `null`:

    localStorage.setItem("projects", JSON.stringify([
      { id: 1, title: "Хороший", description: "Ок" },
      { id: 2, title: "Без описания" },
      null
    ]));
    location.reload();

Ожидалось: отфильтровываются невалидные записи, рендерится только валидная.
Результат:  на странице одна карточка «Хороший», в консоли ошибок нет.

 2. Не массив в хранилище
    localStorage.setItem("projects", JSON.stringify({ foo: "bar" }));
    location.reload();

Ожидалось: `load()` видит, что это не массив, и делает fallback на `testProjects`.
Результат:  показываются 5 тестовых проектов.

 3. Битый JSON
    localStorage.setItem("projects", "не json {");
    location.reload();

Ожидалось:`JSON.parse` бросает исключение, `catch` возвращает `testProjects`.
Результат: ✅ 5 тестовых проектов, страница не падает, ошибок в консоли нет.

 4. Пустое хранилище + добавление через форму
    localStorage.removeItem("projects");
    location.reload();

Затем добавил проект через форму и нажал F5.

Ожидалось: после сброса показываются тестовые данные, добавленный проект сохраняется после перезагрузки.
Результат:  всё работает, `localStorage` содержит новый массив с добавленной записью.

Вывод

Функция `load()` корректно обрабатывает:
- битый JSON (через `try/catch`);
- данные, не являющиеся массивом (через `Array.isArray`);
- записи без обязательных полей (через `isValidProject()`);
- пустое хранилище (fallback на `testProjects`).

Валидные данные при этом не режутся — проверено сценарием 4.
